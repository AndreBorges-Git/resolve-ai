3. O QUE OLHAR PRIMEIRO
--------------------------------------------------------------------------

O diferencial do projeto e a TRILHA DE AUDITORIA: toda mudanca de status grava
um registro de historico na mesma operacao, com desfazimento se a segunda
escrita falhar. Nao existe caminho no sistema que mova o status sem deixar
rastro — nem por rota separada, nem pelo front.

Para ver isso em dois minutos:

  1. Entre como gestor (gestor@resolveai.com / Senha123)
  2. Abra a ocorrencia "Poste apagado na esquina da Praca Central"
  3. A timeline mostra as quatro transicoes, com data, autor e observacao:
     abertura -> aberta -> em_analise -> em_atendimento -> resolvida

A regra de transicao vive no dominio, em api/src/domain/entities/Ocorrencia.js:

  aberta -> em_analise -> em_atendimento -> resolvida
     +----------+---------------+--> cancelada

"resolvida" e "cancelada" sao finais. Transicao fora dessas setas responde 409.


--------------------------------------------------------------------------
4. COMO RODAR LOCALMENTE
--------------------------------------------------------------------------

Um comando, sem configurar nada (o compose traz o proprio MongoDB):

  docker compose up --build

  Front .... http://localhost:5173
  API ...... http://localhost:3000/api

Para popular o banco local com os mesmos dados de demonstracao:

  cd api && npm run seed

Testes (rodam sem banco e sem rede):

  cd api && npm test        -> 146 testes em 20 suites
